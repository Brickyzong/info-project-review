# 向量化知识库（RAG）方案

## 为什么需要向量化

结构化规则（01-10）解决"怎么审"的问题，但评审还需要"参照什么审"——这些参照数据量大、非结构化、需要语义检索，正是向量化（RAG）的用武之地。

## 两层知识架构

```
┌─────────────────────────────────────────────┐
│  第一层：确定性规则（结构化，不向量化）         │
│  01-10 规则文件 → 规则引擎 + prompt 注入       │
│  用途：审查逻辑、阈值判定、禁止项匹配           │
├─────────────────────────────────────────────┤
│  第二层：非结构化参照（向量化，RAG 检索）       │
│  政策文件/历史项目/产品名录 → 向量库 → 相似检索 │
│  用途：判重比对、合规依据、历史参照、概算对标    │
└─────────────────────────────────────────────┘
```

## 需要向量化的数据

| 数据类别 | 内容 | 用途 | 检索方式 |
|----------|------|------|----------|
| 政策法规库 | 政务信息化管理办法、信创政策、云资源管理规范 | 合规审查时检索相关条款作为依据 | 语义检索 |
| 历史项目库 | 历年申报项目的名称、建设内容、功能描述、预算 | 判重比对：语义相似度匹配 | 向量相似度 |
| 信创产品库 | 国产芯片/OS/数据库/中间件产品名录及参数 | 信创合规：方案中的产品名与名录匹配 | 精确+语义 |
| 政务云资源库 | 已部署系统清单、已批准云资源清单 | 云资源核查：项目是否在册 | 精确匹配 |
| 历史中标价格库 | 各类项目分项费用中标价 | 二期概算评估：申报金额与历史区间比对 | 数值+语义 |
| 绩效数据库 | 各项目年度绩效评分 | 绩效考核风险：按项目名检索 | 精确匹配 |

## 向量化方案选型

| 方案 | 适用场景 | 本项目推荐 |
|------|----------|:----------:|
| **ChromaDB** | 轻量级，Python 原生，零运维，适合单机部署 | ✅ 一期首选 |
| **FAISS** | 高性能，纯向量检索，无元数据管理 | 备选 |
| **Milvus** | 企业级，分布式，政务场景 | 二期扩展 |
| **Qdrant** | Rust 编写，高性能，有过滤条件检索 | 二期可选 |

**推荐 ChromaDB**：
- Python 原生，FastAPI 可直接集成
- 支持 metadata 过滤（如按年份、项目类型筛选历史项目）
- 嵌入式模式，无需额外服务进程
- 政务外网单机部署，零运维成本

## 架构设计

```
评审引擎调用 RAG 的典型场景：

1. 项目判重：
   方案文档 → 提取建设内容 → embedding → 向量检索历史项目库
   → 返回 Top-5 相似项目 → LLM 判断是否构成重复

2. 信创合规：
   方案中提取产品名 → 精确匹配 + 语义检索信创产品库
   → 返回匹配结果 → 规则引擎判定合规

3. 合规依据引用：
   审查项触发 → 语义检索政策法规库
   → 返回相关条款原文 → 作为审查报告"参考依据"字段

4. 概算评估（二期）：
   方案预算 → 提取分项费用 → 检索历史中标价格库
   → 返回参考区间 → 计算偏差幅度
```

## 评审时 RAG 调用流程

```
方案文档上传
  │
  ├─ 文档解析（提取结构化信息）
  │
  ├─ [RAG] 判重智能体
  │   ├─ 建设内容 → embedding
  │   ├─ 向量检索历史项目库 → Top-N 相似项目
  │   └─ LLM 比对分析 → 判重结论
  │
  ├─ [规则] 准入门槛审查（不调 RAG，纯规则匹配）
  │
  ├─ [规则] 方案完整性检查（不调 RAG，章节匹配）
  │
  ├─ [RAG] 信创合规检查
  │   ├─ 提取选型产品名
  │   ├─ 检索信创产品库
  │   └─ 规则引擎判定合规
  │
  ├─ [RAG] 绩效考核风险
  │   ├─ 项目名称 → 检索绩效数据库
  │   └─ 阈值判定
  │
  ├─ [RAG] 政务云资源核查
  │   ├─ 项目名称 → 检索政务云资源库
  │   └─ 清单匹配判定
  │
  └─ 报告生成（汇总所有审查结果）
```

## 一期实施建议

一期先上 **判重 RAG**（这是核心差异化能力），其他规则类审查用规则引擎：

| 优先级 | RAG 场景 | 理由 |
|--------|----------|------|
| P0 | 历史项目判重 | 纯规则无法判重，必须语义比对 |
| P1 | 信创产品库 | 产品名录量大，需要检索 |
| P2 | 政务云清单 | 可用精确匹配，不一定需要向量化 |
| P3 | 政策法规库 | 合规依据引用，锦上添花 |
| P4 | 绩效数据库 | 精确匹配即可 |
| 二期 | 历史中标价格库 | 概算评估用 |
