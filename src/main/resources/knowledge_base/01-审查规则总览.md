# 审查规则总览

## 来源
- 《信息化项目建设方案.docx》
- 《信息化项目评审智能体工作流.docx》（泰兴市数据局）

## 设计原则
**先判属性、再行审核、分类处置、全程留痕**

## 主流程

```
文档解析 → 项目判重 → 分类路由 → 智能审查 → 报告生成
```

| 步骤 | 节点 | 说明 |
|------|------|------|
| 1 | 文档解析 | 自动读取方案文档，提取项目名称、建设内容、技术方案等关键信息 |
| 2 | 项目判重 | 语义理解识别项目类型（建设/运维）及子类型（新建/续建/改建），与历史项目库全量比对，判断是否重复建设 |
| 3 | 分类路由 | 重复建设→直接结束；运维类→运维审查路径；建设类（不重复）→建设审查路径 |
| 4 | 智能审查 | 建设类执行六项审查，运维类执行四项审查 |
| 5 | 报告生成 | 自动汇总审查结果，生成标准化审核报告和结构化修改建议书 |

## 审查类型对比

| 审查项 | 建设类 | 运维类 |
|--------|:------:|:------:|
| 重复性核查 | ✓ | - |
| 准入门槛审查 | ✓ | ✓ |
| 方案完整性检查 | ✓（八章） | ✓（五章） |
| 信创合规检查 | ✓ | - |
| 绩效考核风险 | ✓（续建/改建） | ✓ |
| 政务云资源核查 | ✓ | ✓ |

## 三大智能体
1. **项目判重智能体**：识别项目类型+子类型，与历史库比对判重
2. **建设项目审查智能体**：执行六项合规性审查
3. **运维项目审查智能体**：执行四项合规性审查

## 系统四层架构

| 层级 | 职责 | 主要内容 |
|------|------|----------|
| 用户层 | 服务入口 | 项目申报单位在线提交、评审专家辅助审查、管理员系统运维 |
| 应用层 | 业务编排 | 项目判重智能体、建设项目审查智能体、运维项目审查智能体 |
| 能力层 | 技术引擎 | 大语言模型、语义理解、知识库检索、规则引擎、OCR识别 |
| 数据层 | 数据底座 | 历史项目库、绩效数据库、政务云资源库、信创产品库、标准模板库 |

## 项目规划
- **一期**：嵌入泰兴市项目管理平台，打通"申报—审核—反馈—修改—复审"全链条
- **二期**：拓展概算智能评估能力，对标国标GB/T 36964，偏差超30%自动预警
